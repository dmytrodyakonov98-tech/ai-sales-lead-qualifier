# M001-B001 First Deterministic Vertical Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and prove one local-form lead reaches exact-hash human approval, commits once to the built-in CRM inbox, materializes `lead_decision_bundle_v1`, survives restart, and verifies from durable evidence.

**Architecture:** A Python 3.12 standard-library application separates pure deterministic domain functions from a SQLite repository, filesystem SHA-256 CAS, application service, independent verifier, and localhost form adapter. State, approval, destination writes, hashes, and evidence are controlled exclusively by deterministic code.

**Tech Stack:** Python 3.12 standard library, `sqlite3` WAL, `hashlib` SHA-256, `unittest`, `http.server`, canonical UTF-8 JSON.

**Spec:** `docs/superpowers/specs/2026-09-02-m001-b001-design.md`

## Global Constraints

- One inbound channel: localhost form.
- One destination: built-in SQLite CRM inbox.
- No arbitrary local file access and no client-controlled authority.
- No destination row or artifact before exact candidate-hash approval.
- Current-state database plus append-only audit events; not event sourcing.
- Artifact kind is exactly `lead_decision_bundle_v1`.
- Python runtime dependencies are standard-library only.
- Real LLM, external CRM, calendar, generic workflow, queue/leases, and EXE packaging remain deferred from B001.

## File map

- `src/sen_m001/canonical.py`: canonical JSON bytes and SHA-256 helpers.
- `src/sen_m001/domain.py`: normalization, validation, extraction, scoring, explanation, next action, response draft, and candidate construction.
- `src/sen_m001/database.py`: migration, transactions, durable current state, documents, approvals, CRM inbox, artifacts, evidence, and events.
- `src/sen_m001/cas.py`: atomic content-addressed byte storage and reads.
- `src/sen_m001/service.py`: state-guarded pre-approval and approval flows.
- `src/sen_m001/verifier.py`: independent durable-chain verification.
- `src/sen_m001/web.py`: localhost form and approval surface.
- `src/sen_m001/__main__.py`: local launcher.
- `tests/`: executable B001 proof gates.

def test_exact_approval_commits_once_and_verifies_after_restart(self):
    pending = self.service.submit_form(FIXED_FORM)
    first = self.service.approve(pending["run_id"], pending["candidate_sha256"])
    second = self.service.approve(pending["run_id"], pending["candidate_sha256"])
